`Claude Code Ultraplan`은 한마디로 말하면 **계획은 웹에서 더 편하게 다듬고, 실제 구현은 웹이나 내 터미널 중 원하는 곳에서 실행하는 기능**이야.

기존에도 Claude Code에는 plan 모드가 있었지만, 긴 계획을 검토하고 피드백하는 데는 터미널이 조금 답답할 때가 있었어. Ultraplan은 그 계획 단계를 Claude Code on the Web으로 넘겨서, 브라우저에서 더 넓은 화면과 더 좋은 리뷰 인터페이스로 다듬게 해줘.

## 왜 필요한가

코드를 바로 고치기보다 먼저 계획을 세워야 하는 작업이 있어.

예를 들면 이런 경우야.

- 인증 구조를 세션 기반에서 JWT로 바꾸는 작업
- 여러 파일과 서비스가 연결된 리팩토링
- 데이터 모델, API, 마이그레이션 순서를 먼저 정리해야 하는 변경
- 바로 구현하면 위험하고, 먼저 설계 합의가 필요한 작업

이런 작업은 계획 자체가 중요해. 그런데 터미널에서는 긴 문서를 검토하고 부분별로 의견을 남기기 불편할 수 있어. Ultraplan은 바로 그 지점을 해결하려고 나온 기능이야.

## 어떻게 동작하나

흐름은 생각보다 단순해.

1. 로컬 CLI에서 Ultraplan으로 계획 작업 시작
2. Claude Code on the Web이 클라우드에서 저장소를 살펴보고 계획 초안 작성
3. 브라우저에서 계획을 읽고, 특정 문단이나 섹션에 코멘트 남기기
4. Claude가 그 피드백을 반영해 계획 수정
5. 최종적으로 웹에서 바로 구현하거나, 내 터미널로 계획을 되돌려 로컬에서 구현

즉, **계획 수립과 구현 실행을 분리**해주는 흐름이라고 보면 돼.

## 시작 방법

문서 기준으로는 세 가지 방식이 있어.

### 1) `/ultraplan` 명령으로 시작

```bash
/ultraplan migrate the auth service from sessions to JWTs
```

가장 직관적인 방식이야. “이건 Ultraplan으로 계획해줘”라고 명시적으로 시작하는 셈이지.

### 2) 일반 프롬프트에 `ultraplan` 키워드 넣기

평소처럼 프롬프트를 쓰되 `ultraplan`이라는 단어를 포함하면 Ultraplan 흐름으로 들어갈 수 있어.

### 3) 로컬 plan 결과를 Ultraplan으로 넘기기

로컬에서 Claude가 먼저 계획을 만든 뒤, 승인 화면에서 **웹에서 더 다듬기**를 선택할 수도 있어.

즉, 처음부터 Ultraplan으로 시작할 수도 있고, 로컬 계획을 하다가 중간에 Ultraplan으로 넘길 수도 있어.

## 실행 중 상태 표시

Ultraplan을 시작하면 터미널 입력창에 상태가 표시돼.

- `◇ ultraplan` → Claude가 코드베이스를 조사하고 계획을 쓰는 중
- `◇ ultraplan needs your input` → 추가 질문이 있어서 브라우저에서 답변이 필요함
- `◆ ultraplan ready` → 계획 초안이 준비되어 브라우저에서 검토 가능함

터미널은 여기서 계획 초안을 길게 보여주기보다, **원격 세션이 준비됐는지 알려주는 역할**에 가까워.

## 브라우저에서 뭐가 좋아지나

Ultraplan의 핵심은 브라우저 리뷰 경험이야.

문서에서 강조하는 장점은 이거야.

- **인라인 코멘트**: 계획 전체가 아니라 특정 부분만 정확히 짚어서 피드백 가능
- **이모지 반응**: 가볍게 승인하거나 우려를 표시 가능
- **아웃라인 사이드바**: 긴 계획을 섹션 단위로 빠르게 이동 가능

이게 왜 중요하냐면, 계획이 길어질수록 “전체적으로 수정해줘”보다 “이 단계 순서를 바꿔줘”, “이 리스크는 빠졌어”처럼 **부분 피드백**이 훨씬 생산적이기 때문이야.

## 어디서 실행할 수 있나

계획이 마음에 들면, 마지막에 실행 위치를 고를 수 있어.

### 1) 웹에서 바로 구현

브라우저에서 **Approve Claude's plan and start coding**를 누르면, 같은 웹 세션이 그대로 구현까지 이어서 진행해.

이 방식은 이런 경우에 잘 맞아.

- 로컬 환경을 쓰지 않아도 되는 작업
- GitHub 중심으로 바로 PR까지 만들고 싶은 경우
- 내 컴퓨터를 계속 켜두고 싶지 않은 경우

구현이 끝나면 웹에서 변경 사항을 검토하고 PR을 만들 수 있어.

### 2) 계획을 터미널로 되돌리기

브라우저에서 **Approve plan and teleport back to terminal**를 누르면, 계획만 로컬 터미널로 보내서 내 환경에서 구현하게 할 수 있어.

이 옵션이 좋은 경우는 이래.

- 로컬 환경 변수, 데이터베이스, 사내 도구 접근이 필요한 경우
- 내 컴퓨터에서 직접 테스트해야 하는 경우
- 클라우드보다 로컬 환경이 더 완전한 경우

터미널로 돌아오면 보통 세 가지 선택지가 보여.

- **Implement here**: 지금 대화 흐름 그대로 이어서 구현
- **Start new session**: 계획만 들고 새 세션에서 깔끔하게 시작
- **Cancel**: 실행은 하지 않고 계획만 파일로 저장

이 구조가 꽤 좋아. 계획을 승인했지만, 구현은 지금이 아닐 수도 있으니까.

## Ultraplan이 특히 잘 맞는 상황

내 기준에는 이런 작업에서 특히 유용해 보여.

### 큰 리팩토링 전 설계 정리

바로 수정하기 전에 파일 영향 범위, 마이그레이션 순서, 롤백 전략까지 먼저 보고 싶을 때 좋아.

### 팀 리뷰 전에 계획 합의

코드를 고치기 전에 “이 방향으로 가도 되는가”를 웹에서 문서처럼 검토하기 좋다.

### 터미널을 비워두고 싶을 때

계획 초안 작성이 클라우드에서 돌아가니까, 그동안 로컬에서는 다른 작업을 할 수 있어.

### 웹과 로컬을 상황에 따라 나누고 싶을 때

계획은 웹에서, 구현은 로컬에서. 혹은 둘 다 웹에서. 이 선택권이 있다는 게 생각보다 크다.

## 사용 조건과 제한

문서 기준으로는 몇 가지 전제가 있어.

- Claude Code on the Web 계정이 필요함
- GitHub 저장소가 필요함
- Claude Code v2.1.91 이상 필요함
- 연구 프리뷰 기능이라 동작과 UI가 바뀔 수 있음
- Anthropic 클라우드에서 동작하므로 Bedrock, Vertex AI, Foundry에서는 사용 불가

특히 마지막이 중요해. Ultraplan은 클라우드 세션이 핵심이기 때문에, 완전 로컬/타 클라우드 배포 환경과는 잘 맞지 않을 수 있어.

## 한 줄로 정리하면

`Claude Code Ultraplan`은 **계획 수립을 브라우저 중심으로 더 정교하게 만들고, 구현은 웹 또는 로컬 중 상황에 맞게 선택하게 해주는 기능**이야.

단순히 “원격 실행”만 하는 기능이 아니라, **계획을 검토하고 합의하는 단계 자체를 더 좋게 만든다**는 점에서 의미가 있어.

## 핵심 요약

- 계획 초안을 클라우드의 Claude Code on the Web이 작성한다
- 브라우저에서 섹션별 코멘트와 수정 요청을 할 수 있다
- 계획 승인 후 웹에서 바로 구현하거나 터미널로 되돌릴 수 있다
- 큰 리팩토링, 설계 변경, 합의가 필요한 작업에 특히 유용하다
- GitHub 저장소와 Claude Code on the Web 계정이 필요하다
- 연구 프리뷰 기능이며 일부 환경에서는 지원되지 않는다
