`Meta-Harness`는 모델이 잘 풀도록 도와주는 **하네스(harness)**를 자동으로 개선해 주는 최적화 프레임워크야.

보통 우린 프롬프트나 retrieval 규칙을 바꿔가며 성능을 올리는데, 거기서 멈추는 게 아니라
`Meta-Harness`는 **전체 후보 코드, 실행 로그, 점수까지 파일시스템에 남기고** 그걸 다음 후보 생성에 그대로 써.

한마디로, “요약한 점수만 보고 추측”이 아니라 “실패한 이유를 직접 읽고 고치기”가 가능해져.

![Meta-Harness 공식 썸네일](/images/posts/meta-harness-site.svg)


## 핵심 아이디어 한 줄

기존 최적화는 보통 직전 결과나 요약 점수만 보고 후보를 바꾸지만, Meta-Harness는
**과거 전체 실행 로그를 탐색 가능한 파일시스템으로 공개**해서 다음 후보가 근거 기반으로 개선되게 만든다.

## 왜 다르냐면

기존 방법이 보는 정보량은 대체로 작아.
- Self-Refine: 마지막 출력 + 비평
- OPRO: 최근 점수 페어 위주
- MIPRO/AlphaEvolve: 코드/요약 점수 정도

반면 Meta-Harness는 이렇게 본다.
- 모든 후보의 소스 코드
- 실행 트레이스(프롬프트, 도구 호출, 에러)
- 점수와 로그

즉, 단계당 약 **최대 10M 토큰**까지 진단 정보 접근 가능.

이게 왜 중요하냐면, 에이전트가 “왜 실패했는지”를 추적해서 특정 결정 지점만 고치면 돼서
새 실험이 더 효율적으로 이동해.

## 검색 루프를 어떻게 쓰나

아주 단순히 4단계야.

1. 제안자(코딩 에이전트)가 다음 하네스 후보를 작성
2. 후보를 벤치마크에 적용해 평가
3. 소스/로그/점수를 파일시스템에 기록
4. 기록을 다시 읽고 다음 후보 제안

이걸 반복해서 후보가 점점 좋아지는 방식이야.

### 실험 결과 요약

![텍스트 분류 및 학습곡선 비교](/images/posts/meta-harness-learning-curves.svg)

#### 텍스트 분류

- LawBench: `40.9%` → `48.6%`
- 대회에서 쓰는 few-shot 대비 더 적은 문맥(약 `45.5K`)으로 동등 이상 성능 달성

#### 수학 추론

- 5개 모델에서 평균 `+4.7` 포인트 상승
- 특히 검색+리트리버 설계를 하네스로 최적화해서 전달력이 좋아짐

#### Agentic coding (TerminalBench-2)

- Claude Opus 4.6: `76.4%` (상위권)
- Claude Haiku 4.5: `37.6%` (1위)

## 결론적으로

이건 단순 성능 튜닝이 아니라, **학습/평가/개선의 루프를 하네스 단위로 자동화**하는 방식이라고 보면 된다.

정리하면:
- 문제: 기존 최적화는 정보 손실이 커
- 방법: 로그 중심의 전체 히스토리를 제안자에게 제공
- 결과: 더 빨리, 더 정확하게 하네스 개선

## 어디에 써먹기 좋은가

- 텍스트 분류, 수학 문제, 리트리버 설계처럼
- 실패 원인이 복잡한 시스템에서
- 수동 튜닝이 오래 걸리는 워크플로에

반대로, 단발성 실험이거나 히스토리를 관리할 여유가 없다면 과한 장치가 될 수도 있어.

## 한 줄 정리

`Meta-Harness`는 점수만 보는 기존 최적화와 다르게, **실패 로그까지 다시 읽는 구조로 하네스를 진화**시키는 게 핵심이야.
