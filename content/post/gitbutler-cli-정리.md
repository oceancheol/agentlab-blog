`GitButler CLI`는 한마디로 말하면 **기존 Git 저장소 위에서 더 직관적인 브랜치 작업과 이력 편집을 제공하는 새로운 터미널 인터페이스**야.

페이지를 보면 GitButler는 이 CLI를 그냥 보조 도구로 소개하지 않아. 오히려 **Git은 그대로 두고, 사람이 쓰기 더 편하고 AI 에이전트도 다루기 쉬운 Git 경험**으로 밀고 있어. CLI 이름도 짧아. `gitbutler`가 아니라 `but`를 쓴다.

## 뭐가 다른가

기존 Git CLI는 강력하지만, 자주 헷갈리는 지점이 분명히 있어.

- 브랜치를 여러 개 동시에 다루기 번거롭고
- 커밋 순서를 만지거나 변경을 옮길 때 부담이 크고
- `git log`, `rebase`, `reset`, `stash` 같은 조합이 익숙하지 않으면 실수하기 쉽다

GitButler CLI는 이런 불편을 줄이는 쪽에 초점이 있어. 핵심 메시지는 단순해.

> Git의 내부 모델은 유지하되, 사람이 자주 불편해하는 작업 흐름을 더 자연스럽게 바꾸자.

## 설치와 기본 명령

페이지에서 가장 먼저 보이는 설치 방법은 이거야.

```bash
curl -fsSL https://gitbutler.com/install.sh | sh
```

설치 후에는 `but` 명령을 사용해.

예시로 보여주는 명령은 이거야.

```bash
but branch new user-bookmarks
```

즉, 브랜치 생성부터 Git의 기본 명령 체계와는 조금 다른 인터페이스를 제공한다는 뜻이야.

## 핵심 기능 1: Stacked Branches

GitButler가 가장 강하게 미는 개념 중 하나가 **Stacked Branches**야.

이건 쉽게 말하면 기능 하나 위에 다음 기능을 차곡차곡 쌓는 방식이야.

예를 들어,

- 1단계에서 데이터 모델 변경
- 2단계에서 API 추가
- 3단계에서 UI 연결

이렇게 이어지는 작업을 각각 독립 브랜치처럼 다루면서도, 서로 관계가 있는 변경으로 관리하는 흐름이야.

일반 Git에서도 비슷한 작업은 가능하지만, 체감상 꽤 불편해. GitButler는 이걸 기본 개념으로 끌어올려서 더 쉽게 쓰게 하려는 거야.

페이지 설명도 명확해.

- 기능 위에 기능을 쌓을 수 있고
- 머지 충돌을 줄이고
- 리뷰와 머지를 더 독립적으로 진행할 수 있다는 방향이야

복잡한 기능 개발이나 작은 PR 여러 개로 쪼개는 워크플로에 잘 맞아 보여.

## 핵심 기능 2: Parallel Branches

또 하나 흥미로운 건 **Parallel Branches**야.

이건 여러 작업 브랜치를 동시에 다루는 개념인데, 핵심 메시지는 “브랜치 전환에 덜 매이게 하겠다”에 가까워.

보통 Git에서는 작업 A를 하다가 작업 B를 보려면 checkout을 바꾸고, 상태를 확인하고, 다시 돌아오는 흐름이 귀찮아. GitButler는 여러 브랜치를 병렬로 보는 작업 감각을 강조해.

즉,

- 작업 A
- 작업 B
- 실험용 수정

이런 걸 계속 오가야 할 때 컨텍스트 전환 비용을 낮추겠다는 접근이야.

## 핵심 기능 3: Unlimited Undo

이 기능은 꽤 직관적으로 와닿아.

Git 쓰면서 제일 무서운 순간 중 하나가 “잘못 건드렸는데 되돌릴 수 있나?”일 때잖아. Git 자체도 되돌리기 방법이 많지만, 그만큼 헷갈리기도 해.

GitButler는 **Unlimited Undo**를 전면에 내세워.

즉,

- 실수해도 다시 되돌리기 쉽고
- 커밋 이후 작업도 다시 조정할 수 있고
- undo/redo 감각으로 Git 조작을 더 안전하게 하겠다는 거야

이건 Git 초보자뿐 아니라, Git을 오래 쓴 사람에게도 꽤 매력적인 포인트야. 강력한 도구일수록 복구가 쉬워야 마음이 놓이니까.

## 핵심 기능 4: Smartlog와 이력 편집

페이지에는 **Powerful Smartlog**와 **Simple history editing**도 같이 나온다.

### Powerful Smartlog

여기서는 복잡한 `git log` 대신, 현재 활성 브랜치와 변경 흐름을 더 읽기 쉽게 보여준다는 점을 강조해.

Git 로그가 익숙하지 않은 사람에게는 특히 반가운 부분이야. “지금 내가 어디에서 뭘 쌓고 있는지”를 더 명확하게 보여주는 쪽이니까.

### Simple history editing

이건 커밋 이력 편집을 더 단순하게 만들겠다는 메시지야.

페이지에서는 이런 표현을 써.

- 변경을 커밋 사이에서 옮기기
- absorb
- reorder
- amend

즉, 일반 Git에서 인터랙티브 리베이스나 수동 조작으로 하던 일을 더 쉽게 만들겠다는 뜻이야.

## AI 코딩에 왜 잘 맞는가

이 페이지에서 가장 요즘 느낌이 나는 부분은 **Agent-Optimized** 섹션이야.

여기서 GitButler는 자신들을 단순한 Git UX 개선 도구가 아니라, **AI 에이전트가 다루기 좋은 Git 인터페이스**로 소개해.

핵심 포인트는 이래.

- **Structured output**: 자동화와 스크립트가 읽기 좋은 출력
- **Predictable commands**: 명령 결과가 더 예측 가능함
- **Scripting ready**: 자동화 워크플로에 붙이기 쉬움

이게 왜 중요하냐면, AI 코딩 에이전트는 화면보다 **일관된 명령 체계와 읽기 쉬운 출력**을 더 잘 다뤄. 일반 Git도 물론 자동화할 수 있지만, 실제로는 예외 케이스와 해석 비용이 꽤 커.

그래서 GitButler CLI는 사람에게 편한 도구이면서 동시에, Codex나 Claude Code 같은 에이전트 워크플로에도 잘 맞는 방향으로 설계된 것처럼 보여.

## Git을 대체하는가

내 느낌은 “완전 대체”보다는 **Git 위에 올라가는 새로운 작업 인터페이스**에 더 가까워.

중요한 건 이거야.

- 기존 Git 저장소와 함께 쓸 수 있고
- Git 개념을 버리기보다 더 다루기 쉽게 감싸고
- 브랜치, 이력, 리뷰 흐름을 재구성한다

즉, Git 자체를 없애겠다는 느낌보다는, **Git이 가진 거친 사용 경험을 부드럽게 다시 디자인한다**는 쪽이 더 정확해.

## 누가 써보면 좋을까

이 도구는 특히 세 부류에게 잘 맞아 보여.

### 1) 브랜치 전략이 자주 꼬이는 개발자

작업을 잘게 나눠 PR 올리고 싶은데, 브랜치 관계가 자꾸 복잡해지는 사람에게 잘 맞을 수 있어.

### 2) Git 이력 편집이 늘 부담스러운 사람

리베이스, amend, reset이 늘 긴장된다면 GitButler 방식이 더 편할 가능성이 있어.

### 3) AI 코딩 워크플로를 자주 쓰는 사람

AI 에이전트가 여러 브랜치를 만들고, 바꾸고, 정리하는 흐름을 많이 쓴다면 일반 Git보다 더 안정적인 인터페이스가 될 수 있어.

## 한 줄로 정리하면

`GitButler CLI`는 **기존 Git 저장소는 그대로 두고, 브랜치 관리와 이력 편집을 더 직관적으로 바꾸는 `but` 기반 Git 인터페이스**야.

특히 stacked branches, parallel branches, unlimited undo 같은 개념을 앞세우면서, 사람뿐 아니라 AI 에이전트도 다루기 쉬운 Git 경험을 만들겠다는 방향이 분명해.

## 핵심 요약

- GitButler CLI의 명령 이름은 `but`다
- 설치는 `curl -fsSL https://gitbutler.com/install.sh | sh` 방식으로 안내한다
- stacked branches와 parallel branches를 핵심 개념으로 민다
- unlimited undo와 쉬운 history editing을 강하게 강조한다
- structured output과 predictable commands로 AI 코딩 워크플로를 겨냥한다
- Git 자체를 없애기보다 Git 위의 더 좋은 인터페이스를 만들려는 도구에 가깝다
