`Claude Code Auto Mode`는 한마디로 말하면 **Claude가 도구를 쓸 때마다 매번 승인 받지 않도록, 안전한 작업은 자동으로 진행해주는 중간 모드**야.

기존에는 Claude Code가 파일을 쓰거나 bash 명령을 실행할 때마다 사용자 승인을 자주 물었어. 그러다 보니 긴 작업을 맡기면 중간중간 계속 끊기기 쉬웠지. Auto Mode는 그 불편함을 줄이면서도, 완전히 무조건 실행하는 위험한 방식은 피하려는 절충안이야.

## 왜 필요한가

개발할 때 가장 답답한 순간은 이런 거야.

- 파일 몇 개만 바꾸는 건데 매번 승인 요청이 뜰 때
- 긴 작업을 맡겨 놓고 자리를 비우고 싶은데 계속 멈출 때
- 그렇다고 완전 무제한 실행은 너무 위험할 때

Auto Mode는 이 사이를 메워줘.

즉, **완전 수동 승인**과 **완전 무제한 실행** 사이의 중간 지점이라고 보면 돼.

## 어떻게 동작하나

문서에서 설명하는 방식은 꽤 단순해.

- Claude가 도구를 호출하기 전에 분류기(classifier)가 먼저 본다
- 위험해 보이는 작업은 차단한다
- 안전하다고 판단한 작업은 자동으로 진행한다
- 위험한 행동이 반복되면 결국 사용자 승인으로 넘어간다

여기서 중요한 건, 이 모드가 단순히 승인을 생략하는 게 아니라 **위험도를 보고 판단한다**는 점이야.

## 무엇이 차단되나

예시로는 이런 것들이 막힐 수 있어.

- 대량 파일 삭제
- 민감 데이터 유출 가능성이 있는 작업
- 악성 코드 실행처럼 보이는 행동

반대로 일반적인 코드 수정, 읽기, 덜 위험한 명령은 자동으로 지나갈 수 있어.

## 기존 방식과 비교하면

### 기존 기본 권한 모드

- 파일 쓰기마다 승인
- bash 명령마다 승인
- 안전하지만 너무 자주 끊김

### `--dangerously-skip-permissions`

- 거의 다 통과
- 하지만 너무 위험함
- 격리된 환경이 아니면 비추천

### Auto Mode

- 안전한 작업은 자동 승인
- 위험한 작업은 차단
- 장기 작업에 더 잘 맞음

즉, Auto Mode는 현실적인 타협안이야.

## 누가 쓰면 좋나

- 긴 리팩토링이나 반복 수정이 많은 사람
- Claude Code를 작업 도우미처럼 오래 돌리고 싶은 사람
- 승인 팝업 때문에 흐름이 자꾸 끊기는 사람
- 그렇다고 무제한 실행은 불안한 사람

이런 사람에게 특히 잘 맞아.

## 주의할 점

이 모드가 있다고 해서 완전히 안전한 건 아니야.

- 격리된 환경 사용이 여전히 권장돼
- 분류기가 모든 위험을 완벽하게 잡는 건 아니야
- 반대로 무해한 작업이 가끔 막힐 수도 있어
- 토큰 소비, 비용, 지연 시간이 조금 늘 수 있어

그래서 “편해진다”와 “무조건 안전하다”는 다른 말이야.

## 활성화 방법

문서 기준으로는 사용 환경별로 조금 달라.

- CLI에서는 `claude --enable-auto-mode`로 활성화
- 세션 내에서 `Shift+Tab`으로 전환
- 데스크톱이나 VS Code 확장에서는 설정에서 토글을 켜야 함
- 조직 설정에서 비활성화될 수도 있음

## 한 줄로 정리하면

`Claude Code Auto Mode`는 Claude가 도구를 쓸 때 안전한 작업은 자동으로 진행하고, 위험한 작업은 막아주는 중간 퍼미션 모드야.

승인을 덜 묻기 때문에 작업 흐름이 훨씬 부드러워지지만, 완전 무제한 실행과는 다르다.

## 핵심 요약

- 승인 요청을 줄여주는 중간 모드다
- 분류기가 위험도를 보고 자동 진행 여부를 판단한다
- 대량 삭제, 유출, 악성 행위는 차단할 수 있다
- 장기 작업에 유리하지만 완전 안전하진 않다
- CLI, 데스크톱, VS Code에서 설정 방식이 조금씩 다르다
